2️⃣ Tier Definitions (NON-NEGOTIABLE)
🔴 Tier 1 — STRUCTURAL HARD FAIL (compiler errors)

Purpose:
Guarantee the output is structurally executable by the pipeline + player.

If Tier 1 fails → STOP IMMEDIATELY. NO SEMANTIC RETRY.

Tier-1 checks (KEEP AS HARD FAIL)

These stay exactly hard:

Sections & ordering

missing intro

missing summary

missing memory

missing recap

Core structure

missing renderer

missing visual_beats

missing display_directives

display_directives is null

visual_beats empty when required by schema

Counts enforced at schema level

recap scenes ≠ exactly 5

memory flashcards ≠ exactly 5

Layer logic

missing display directive for any segment_id

text + complex visual visible simultaneously

example section without stepwise visualization

Renderer contracts

renderer="manim" but no manim_scene_spec

renderer="remotion" but no motion spec

renderer="video" but no video beats

✅ Tier-1 is deterministic. LLM must obey or retry structurally.

🟠 Tier 2 — SEMANTIC RETRY (repairable content gaps)

Purpose:
Fix content completeness once structure is correct.

If Tier 2 fails → trigger SEMANTIC RETRY (max 1).

Move THESE from hard-fail → semantic retry

content narration < 150 words

example narration < minimum

recap narration < 300 words

recap narration > 500 words

formula mentioned but no visual beat yet

insufficient explanation depth (measured heuristically, not stylistically)

These are LLM-expandable problems, not structural errors.

❗ Tier-2 failures must:

preserve structure

preserve ordering

only expand or add missing content

🟡 Tier 3 — QUALITY WARNINGS (non-blocking)

Purpose:
Detect style issues without blocking production.

Tier-3 NEVER fails a job.

Move THESE to warnings only

vague visual language:

“clear diagram”

“appropriate animation”

“educational visualization”

repetitive phrasing

overly generic scene descriptions

mild redundancy

These are editorial polish issues, not correctness issues.

You may:

log them

show them in QA dashboards

optionally run a future “polish pass”

But they must not affect control flow.

🔹 validator_orchestrator.py (brain)
def validate(presentation):
    tier1_errors = validate_structural(presentation)
    if tier1_errors:
        return ValidationResult(
            status="STRUCTURAL_FAIL",
            errors=tier1_errors
        )

    tier2_errors = validate_semantic(presentation)
    if tier2_errors:
        return ValidationResult(
            status="SEMANTIC_FAIL",
            errors=tier2_errors
        )

    tier3_warnings = validate_quality(presentation)

    return ValidationResult(
        status="PASS",
        warnings=tier3_warnings
    )
